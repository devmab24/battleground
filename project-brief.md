# Battleground — Project Brief
## 1. What are we actually building? (Scope)

A web app where you type in two fighters and get an AI generated verdict on who'd win, plus AI generated character art for both.

## 2. What's the smallest, simplest version worth shipping (MVP)?

Two text inputs, a Fight button, a working verdict with art, a loading state while we wait on the API, and a basic BattleDex saved in the browser (IndexedDB). Type two fighters, get a real result, save it if you want.

## 3. What are we building this with (tech stack)?

- **Frontend**: HTML, CSS, and vanilla JS.
- **Hosting + backend**: Vercel (Hobby plan) with serverless functions. All API keys live server-side only.
- **AI text (character generation + battle reasoning)**: a free-tier LLM provider (candidates: Google Gemini API, Groq, Cloudflare Workers AI). Verify current free limits before picking.
- **AI images**: a free-tier image provider (candidates: Cloudflare Workers AI, Pollinations.ai). Verify current free limits before picking.
- **Provider layer**: each AI call goes through one small server-side module with a `mock` mode (default in development) that returns fake data and placeholder art. Swapping providers = changing one file/env var.
- **Rate limiting store**: Upstash Redis (free tier).
- **BattleDex storage**: IndexedDB (stores image Blobs directly, much larger quota than localStorage).

Budget: **$0**. Public site, built for fun / skill testing.

## 4. What's the long-term vision, beyond just the MVP?

I would eventually like a real backend where BattleDex characters sync across devices instead of just living in the browser. I'd also want a quick re-fight option using characters already saved in the BattleDex, instead of typing two new ones every time.

## 5. Decisions

### Characters
- A BattleDex entry is a **character**, not a fight. Fights are computed from two saved characters.
- A character is generated by the AI **once**, the first time a name is entered, then saved and reused (stats, moves and image). This keeps results consistent and saves free-tier quota.
- The server **validates and clamps** every AI-generated character against the schema below before returning it. Invalid output is retried once, then rejected with an error.
- Users can't edit stats in the MVP (keeps fights fair). Possible later feature.

Character shape:

```js
{
  id: "uuid",
  name: "Goku",                 // trimmed, 1–50 chars
  types: ["fire"],              // 1–2 types from a fixed list defined in code
  stats: {                      // each 1–100, total capped (e.g. 300) so nothing is maxed everywhere
    hp: 80, attack: 90, defense: 60, speed: 70
  },
  moves: [                      // exactly 4
    { name: "Ki Blast", type: "fire", power: 70, accuracy: 90 }
  ],
  image: Blob | null,           // null = show placeholder art
  createdAt: "ISO date"
}
```

- The type list and type-matchup chart are **our own** (original names and matchups), defined in one file in code.

### Fights
- **The winner is decided by a battle formula in JavaScript**, not by the AI. It uses stats, type matchups and moves. Deterministic: the same two characters always give the same result.
- Speed breaks ties, then a seeded coin flip based on the two character ids. **No draws.**
- **The AI only writes the reasoning**, given the formula's result. It returns JSON: `{ winner, reasoning }`. If the AI call fails, a template sentence is shown instead, so a fight never fails because of the AI.

### Images
- One image per character (group inputs like "10 cows" still get one image).
- Character text and image are requested **in parallel**. The character card shows as soon as the text is ready; the image fills in when it arrives.
- **An image failure or refusal never blocks anything.** The character is saved with placeholder art and can retry image generation later.
- Images are resized/compressed client-side (canvas → WebP/JPEG) before saving to IndexedDB.

### Input handling
- Names are trimmed, 1–50 characters, empty input blocked in the UI and on the server.
- User input is passed to the AI as data inside clearly marked fields, with instructions to treat it only as a character name (basic prompt-injection defence).
- Real people and copyrighted characters are allowed as input. Whatever the image provider refuses falls back to placeholder art (see Images).

### Rate limiting
- 5 requests per minute per IP, **plus a daily cap of 50 per IP**, stored in Upstash Redis.
- Only requests that call the AI count (creating a character, writing reasoning). Re-fights between saved characters cost almost nothing.

### UI states
Every request has a defined state:
- **Loading**: per-character progress (text first, then image).
- **API error**: friendly message + retry button.
- **Rate limited**: "Slow down, try again in X seconds."
- **Storage full**: message asking the user to delete old BattleDex entries.
- **Image refused / failed**: placeholder art + "retry image" button.
